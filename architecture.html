Architecture

NXS Integration (Hot-path Safe)

When an event is classified, the engine calls nxs::on_event. The path is carefully designed so the fuzzer never blocks on external processes.

  • Write metadata JSON to nxs-meta/
  • Resolve the configured NXS set for the event
  • Apply rate limits (cooldown, per-event, total)
  • Spawn each allowed binary non-blocking
  • Hand the Child to the background reaper
  • Exit code 2 → secondary finding recorded in JSONL + atomic counter

The reaper thread polls with try_wait every 250 ms. Zombies are cleaned without ever touching the worker hot path.

Coverage Pipeline

  1. Nexsiz creates / attaches the SHM region (/nexsiz-cov-<id>, 65536 bytes)
  2. Map is zeroed before every execution
  3. Frida agent (or software provider) increments edge cells: (prev >> 1) ^ cur
  4. After execution the provider harvests hits and feeds the state / scheduling layer

Design Constraints

Minimal Dependencies

Default build uses only libc. LibAFL, serde, and related crates are strictly optional behind the libafl feature.

Trait-based Extensibility

New Protocol, Integrity, Oracle, or Encryptor implementations can be registered at runtime without recompiling the core.

Operational Silence

No unnecessary noise. Status lines, secondary findings, and NXS logs are intentional and structured.

Reproducibility

Deterministic RNG seed, structured meta files, and minimised crash inputs support later analysis and reporting.
