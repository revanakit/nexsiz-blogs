Features

Everything that makes Nexsiz capable of exploring deep protocol state machines while remaining operationally reliable.

Core Capabilities

01

Semantic Mutation

Hierarchical field / message / sequence mutators that preserve protocol grammar instead of producing pure noise.

02

Integrity Repair

Automatic restoration of length fields, checksums, framing, and terminators after every mutation.

03

Hybrid Coverage

Black-box response observation + true grey-box edge coverage via AFL-style SHM map and Frida agent.

04

State Awareness

Hybrid state tracker combined with adaptive transition prediction to bias toward promising paths.

05

Connection Reuse

Intelligent stateful TCP reuse with safety-prefix detection to avoid cross-test contamination.

06

NXS Existence Scripts

Post-event actors that deepen findings (repro, differential, timeout, notify) without blocking the hot path.

Plugin System

Trait-based extensibility. Register new behaviour without touching the core.

Protocol Models

Built-in: ftp, smtp, http, generic. Custom models can be added via the plugin registry.

Integrity Strategies

default, http, ftp, smtp, binary, null — repair length, checksums and framing after mutation.

Oracles

default · strict · crash · hang · coverage
differential · sanitizer · diffsan · expanded

diffsan (differential + sanitizer + coverage) is recommended for deep campaigns.

Encryptors

null · xor · chacha20 · tls-record
Combinations: chacha20+tls, xor+tls

Key material via -k or environment variables.

Coverage Providers

Provider Flag Description
null -C null No coverage feedback (black-box only)
map -C map AFL-style 64 KiB edge map via POSIX shared memory (Frida agent)
software -C software Software-based coverage when external instrumentation is unavailable

For true grey-box: instrument the target with the Frida agent (agents/frida/nexsiz_cov.js) and run Nexsiz with -C map --shm <id>.

Execution Paths

Native Path (default)

Minimal dependency surface. Only libc is required. High-throughput worker pool with intelligent connection reuse and process monitoring.

LibAFL Path (optional)

Enable with --features libafl and -L. Provides LibAFL Executor, hierarchical mutator adapter, and LLMP multi-core launcher.

Campaign Control & Observability

  • RPC surface — Unix domain socket for out-of-process Python campaign control
  • Structured output — crashes, hangs, minimised inputs, NXS meta & findings
  • Deterministic RNG — reproducible campaigns via -r
  • Limits — stop after N executions or after a time budget
  • Verbose logging — full visibility into worker activity and NXS spawns
  • Secondary findings — NXS exit code 2 is escalated and recorded in JSONL
