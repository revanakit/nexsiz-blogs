About Nexsiz

Conventional fuzzers often lose structural validity or state context when targeting complex network protocols. Nexsiz is purpose-built to remain aware of protocol grammar, maintain integrity after mutation, and push deeper into state machines that others leave unexplored.

◆

Precision over Volume

Semantic-preserving hierarchical mutators respect protocol grammar. Every mutation aims for structural validity rather than raw throughput noise.

◈

Hybrid State Model

Black-box response observation combined with true grey-box edge coverage. Adaptive transition prediction biases scheduling toward promising paths.

◇

Operational Resilience

Intelligent connection reuse, rate-limited NXS post-discovery actors, and minimal dependency surface designed for real operational pressure.

○

Existence After Discovery

NXS scripts deepen crashes and hangs automatically — auto-repro, differential probes, timeout analysis, notifications — without bloating the core.

Design Principles

Principle Implementation
Semantic-preserving mutation Hierarchical field / message / sequence mutators that respect protocol grammar
Protocol-aware integrity repair Automatic restoration of length fields, checksums, framing, and terminators after mutation
Hybrid state model Black-box response observation + true grey-box edge coverage
Grey-box instrumentation CoverageProvider trait, AFL-style SHM edge map, external Frida agent
Intelligent connection reuse Stateful TCP reuse with safety-prefix detection to prevent cross-test contamination
Adaptive transition prediction Lightweight predictor that biases mutation scheduling toward promising state transitions
Minimal dependency surface Default build depends only on libc; LibAFL is optional behind a feature flag
Trait-based extensibility Protocol, Integrity, Oracle, and Encryptor plugins may be registered without core changes
Differential & sanitizer oracles Multi-dimensional behavioural divergence and memory-safety / protocol-anomaly detection
NXS existence scripts Post-event executable actors with rate-limited, non-blocking spawn and asynchronous exit observation

Who Is It For

Nexsiz is intended for operational use by offensive security teams, red-teamers, and researchers who need reliable, maintainable tooling under real pressure.

  • Deep protocol state exploration beyond surface-level fuzzing
  • Hybrid black/grey-box campaigns with optional Frida instrumentation
  • Post-crash automation that does not compromise the hot path
  • Extensible plugin architecture for custom protocols, oracles, and encryptors
  • Minimal attack surface and reproducible builds

Philosophy: Offensive tooling must execute correctly, remain maintainable under operational pressure, and preserve the operator’s ability to reason about the exact behaviour the target exhibited.
