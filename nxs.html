Concept

Nexsiz discovers interesting events (crash, hang, new coverage, new state). NXS scripts are executable actors that deepen those findings without increasing the size or complexity of the fuzzer core.

Nexsiz (discovery) → crash / hang / interesting → NXS (existence & depth)

They are not passive handlers. They are full programs that can reproduce, probe, analyse, archive, or notify — and report results via exit codes.

Auto-spawn & Rate Limits

shell
nexsiz -h 10.0.0.5 -p 21 -m ftp --nxs default -v
nexsiz --nxs default --nxs-list          # resolve paths, exit
nexsiz ... --nxs intrusive --nxs-cooldown 60 --nxs-max-per-event 20 -v
nexsiz ... --nxs external -v            # webhook (set NXS_WEBHOOK_URL)

Async Exit-Code Observation

Spawn is non-blocking. A background reaper thread (nxs-reaper) keeps the Child handles and polls with try_wait:

  • Every exit code is logged: [nexsiz/nxs] exit <id> → <code> …
  • Exit 2 (further vulnerability / exploit-assist) is escalated as a secondary finding:
    • Atomic counter visible in status line (nxs_sec)
    • Appended to {output}/nxs-findings/secondary.jsonl
    • Sidecar exit_code written under the NXS --out directory
  • Fuzzer hot-path never waits on NXS; zombies are reaped by the background thread.

Contract Summary

Full binding contract lives in nxs/CONTRACT.md. Key points:

Mandatory global options

  • --crash <path> (or via meta)
  • --target <host:port>
  • --meta <path>, --out <dir>, --event, --model, --minimized
  • --help / --version

Exit codes

CodeMeaning
0Completed normally, no further vulnerability indication
1Operational error (missing file, unreachable target, invalid args)
2Indication of further vulnerability / successful exploit-assist → escalate
3Internal timeout
4Interrupted / cancelled
≥10Script-specific success variants

Metadata JSON

Nexsiz writes a forward-compatible meta file before each spawn. NXS must ignore unknown fields. Minimal schema includes event, target, crash path/id, result outcome, coverage hits, etc.

Search Path Priority

  1. Absolute path given to --nxs
  2. NEXSIZ_NXS_PATH / --nxs-path (colon-separated)
  3. ~/.nexsiz/nxs/bin/
  4. ./nxs/bin/ (cwd)
  5. Relative to nexsiz binary / install prefix

Custom NXS

Templates are provided for C, Go, Python, and Rust.

shell
cp -r nxs/templates/rust ~/.nexsiz/nxs/src/my-chain
cd ~/.nexsiz/nxs/src/my-chain && cargo build --release
cp target/release/nxs-* ~/.nexsiz/nxs/bin/

Follow the contract checklist: support required flags, honour exit codes, ignore unknown meta fields, provide stable id.

Webhook

shell
export NXS_WEBHOOK_URL=http://127.0.0.1:9000/hook
nexsiz ... --nxs external -v

# or manual:
./nxs/bin/nxs-notify-webhook --meta output/nxs-meta/….json --url http://…

HTTPS is not supported in the pure-stdlib client. Terminate TLS at a local proxy or use NXS_NOTIFY_CMD with curl from save-notify.
